# 관리자 회원목록 이름/이메일 마스킹 설계 문서

## 배경

- `GET /admin/users`(관리자 회원목록) 응답이 전체 회원의 이름/이메일을 평문으로 그대로 내려주고, 프론트(`AdminUsersPage.jsx`)도 이를 가공 없이 화면에 표시하고 있다.
- 관리자 계정이 여러 명일 수 있는 구조에서, 화면 캡처·화면 공유·발표 자료 등으로 노출될 가능성이 있는 화면에 다른 회원의 실명/이메일이 그대로 보이는 것은 불필요한 개인정보 노출이다.
- 실무(개인정보보호위원회 가이드라인)에서 통용되는 마스킹 규칙을 적용해, 관리자 화면에서는 항상 마스킹된 값만 보이도록 한다.

## 범위

**포함:**
- `GET /admin/users` 응답의 `name`, `email` 필드를 서버에서 마스킹 처리
- 이름/이메일 마스킹 유틸 함수 및 단위 테스트

**제외 (후속 과제로 남김):**
- 마스킹 해제(원본 보기) 기능 — 이번엔 완전 고정 마스킹으로 결정, 향후 필요해지면 별도 조회 API + 감사로그로 확장
- `loginId` 마스킹 — 대상 아님(이번 범위에서 제외하기로 결정)
- 관리자 화면 외 다른 화면(마이페이지 등 본인 정보 조회)의 마스킹 — 본인 정보이므로 대상 아님

## 핵심 결정사항

| 결정 | 선택 | 근거 |
|---|---|---|
| 적용 위치 | 백엔드 (`AdminUserResponse.from()`) | 프론트에서만 가리면 Network 탭에 원본이 그대로 노출됨. 서버가 마스킹된 값만 내려주면 원본이 클라이언트에 도달하지 않음 |
| 마스킹 대상 필드 | 이름, 이메일만 | `loginId`는 대상 아님. 가입일/권한은 민감정보 아님 |
| 원본 보기 기능 | 없음 (완전 고정 마스킹) | 이번 범위에서 단순하게 유지. 필요해지면 별도 API로 확장 가능한 구조(유틸 함수 분리)로 만들어둠 |
| 이름 마스킹 규칙 | 첫 글자만 노출, 나머지 전부 `*` | 개인정보보호위원회 가이드라인에서 통용되는 방식. 길이에 무관하게 동일 규칙 적용 가능 |
| 이메일 마스킹 규칙 | 로컬파트(`@` 앞) 3자 이상이면 앞 3자 노출+나머지 `*`, 3자 미만이면 앞 1자 노출+나머지 `*`. 도메인은 그대로 노출 | 실무에서 흔히 쓰는 패턴. 도메인까지 가리면 오히려 회원 문의 대응 시 식별성이 과하게 떨어짐 |
| 구현 형태 | `user` 패키지 내 순수 함수 유틸 클래스(`MaskingUtil`) | 부작용 없는 순수 함수라 단위 테스트가 쉽고, 다른 곳에서 마스킹이 필요해져도 재사용 가능 |

## 마스킹 규칙 상세

### 이름 (`MaskingUtil.maskName`)
- `null`/빈 문자열 → 그대로 반환
- 1글자 → 그대로 반환 (가릴 게 없음)
- 2글자 이상 → 첫 글자 + `*` × (전체 길이 - 1)
  - 예: `한승연` → `한**`, `이도` → `이*`, `z z` → `z***`

### 이메일 (`MaskingUtil.maskEmail`)
- `null`/`@` 없는 값 → 그대로 반환 (방어적 처리)
- 로컬파트(`localPart`)와 도메인(`domain`)을 `@` 기준으로 분리
- 로컬파트 길이 ≥ 3 → 앞 3자 + `*` × (로컬파트 길이 - 3)
  - 예: `s2ungyeon.h@gmail.com` → `s2u********@gmail.com`
- 로컬파트 길이 1~2 → 앞 1자 + `*` × (로컬파트 길이 - 1)
  - 예: `ab@gmail.com` → `a*@gmail.com`
- 도메인은 그대로 유지

## 데이터 흐름

`AdminUserController.getUsers()` → `AdminUserService.getUsers()` → `User` 목록 조회 → `AdminUserResponse.from(user)` 내부에서 `MaskingUtil.maskName`/`maskEmail` 호출해 마스킹된 값으로 응답 조립 → 프론트(`AdminUsersPage.jsx`)는 기존 코드 변경 없이 마스킹된 값을 그대로 표시.

## 코드 추가/변경 항목

| 파일 | 변경 |
|---|---|
| `user/util/MaskingUtil.java` (신규) | `maskName(String)`, `maskEmail(String)` 정적 메서드 |
| `user/dto/AdminUserResponse.java` | `from(User)`에서 `name`/`email` 대입 시 `MaskingUtil` 호출로 변경 |
| 프론트 | 변경 없음 |

## 테스트

- `MaskingUtilTest` (신규, JUnit):
  - 이름: null/빈 문자열, 1글자, 2글자, 3글자 이상 케이스
  - 이메일: `@` 없는 값(방어), 로컬파트 1글자, 2글자, 3글자, 3글자 초과 케이스, 도메인 보존 확인
- `AdminUserResponseTest` 또는 기존 `AdminUserService` 관련 테스트에 마스킹된 값이 응답에 반영되는지 검증 케이스 추가 (기존 테스트 파일 존재 여부 확인 후 반영)

## 명시적 경계 사항

- 이 마스킹은 **표시용**이며, DB에는 원본 이름/이메일이 그대로 저장된다 (이메일 인증, 로그인, 알림 발송 등 다른 기능은 원본 값을 그대로 사용해야 하므로 저장 데이터 자체는 건드리지 않음).
- 완전 고정 마스킹이라 관리자가 실제 이메일로 회원에게 연락해야 하는 업무가 생기면 이 기능만으로는 불가능하다 — 필요해지면 별도 "원본 보기" API를 추가하는 후속 작업이 필요하다.
